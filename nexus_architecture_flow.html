What If There Is No End-to-End Connection? Store-Carry-Forward Visual Timeline
"THE NETWORK DOES NOT NEED A CONTINUOUS END-TO-END PATH."
Each node stores validated data and forwards it when a suitable peer becomes available through human physical movement.
TIME 1: ISOLATED INCIDENT
Node A 🚨 ····· (Out of Range) ····· Node B 📱
Node A has an emergency. Node B is temporarily unreachable beyond radio range. Node A safely persists the report to its own local Dexie flash storage.
TIME 2: LOCAL ENCOUNTER
Node A 🚨 ➔ (Synced!) ➔ Node B 📱
Node B walks into radio range. Nodes automatically discover, tie-break, connect, and sync. Node B writes the incident to flash before sending an ACK.
TIME 3: PHYSICAL MOVEMENT
Node B 🚨 ➔ (Relayed!) ➔ Node C 📱
Node B walks across campus/neighborhood and encounters Node C. Node B discovers Node C and relays the stored incident (hopCount becomes 1).
TIME 4: DELIVERY TO BASE
Node C 🚨 ➔ (Delivered!) ➔ Node D 🏥 / Base
Node C reaches medical triage or command station. Emergency beacon delivered without a single cellular tower or internet router active.

⏳ TTL (Time-To-Live)
Default 24-hour expiration limits message lifetime, preventing stale records from circulating indefinitely.
🛑 Protocol Hop Budget
Enforces controlled propagation limits to prevent broadcast storms; it is a safety mechanism, not a device-count limit.
🔑 Stable Device ID
Ensures deterministic deduplication and prevents self-loop echoes across multi-peer clusters.
⚡ Priority Queuing
P0 Emergency distress signals preempt background community notices during radio transfer windows.
🔍 Manifest Comparison Hash
32-byte SHA-256 digests compare local vs. remote record states, cutting radio airtime and battery usage by 95%.

💡 Architectural Decision: Why We Didn't Make WebRTC The Only Transport
Transport Evolution
WebRTC DataChannel
  • ✔ Excellent P2P Data Transport: High-speed binary channels directly between two connected endpoints.
  • ✔ Broad Web Support: Runs seamlessly across modern desktop and mobile browsers.
  • ⚠️ The Local Discovery Challenge: WebRTC requires an external signaling channel (WebSocket / STUN / TURN) to exchange SDP offers/answers before two devices can establish a connection.
  • ⚠️ Not a Radio Discovery Layer: WebRTC itself cannot scan for nearby physical devices over Bluetooth or Wi-Fi Direct without infrastructure.
Google Nearby Connections
  • ✔ True Local Hardware Discovery: Uses Bluetooth Low Energy beacons to discover physical phones nearby with zero network infrastructure.
  • ✔ Autonomous Connection Setup: Negotiates Wi-Fi Direct and Bluetooth sockets directly between devices without any signaling server.
  • ✔ Zero Cloud Dependency: Operates entirely off-grid in deep cellular and internet blackouts.
  • ✔ M-to-N Cluster Strategy: Supports symmetrical simultaneous advertising and discovery (`Strategy.P2P_CLUSTER`).
"We didn't remove WebRTC. We changed its role: Google Nearby is our PRIMARY physical Android transport; WebRTC remains our ALTERNATE transport."

How Far Can It Transmit? Range & Connectivity Reality Physical Radio Characteristics
"Nearby radio communication is environment- and device-dependent; Google Nearby Cluster provides practical local-range peer connectivity."
Actual physical transmission range varies based on phone antenna hardware, physical obstacles (walls, foliage, terrain), electromagnetic interference, and orientation. A reference distance of ~100m is commonly observed in open outdoor line-of-sight conditions.
⚠️ Important Distinction: ≈100m is a reference radio range, NOT a guaranteed NEXUS operating range. Furthermore, GPS distance does NOT determine whether two devices are connected — physical RF signal presence determines real connectivity.
✔ Extending Coverage: Multi-hop store-carry-forward allows messages to travel far beyond single-hop radio range through human and vehicle movement.

Current Limitations Engineering Transparency
•
Radio Range: Physical radio range is environment-dependent; obstacles like thick concrete and metal structures reduce effective distance.
•
Platform Scope: Android is currently the primary physical mesh platform due to Google Play Services Nearby Connections capabilities.
•
Campus Wi-Fi Isolation: Enterprise/campus Wi-Fi networks enforce AP Client Isolation, preventing peer-to-peer LAN sockets without a personal hotspot.
•
GPS Acquisition: Satellite GPS fix speed varies based on cloud cover, indoor positioning, and urban canyon interference.
•
Scale Optimization: Current prototype epidemic routing is optimized for local clusters; large networks require further routing pruning.
•
Trust Model: Production deployments will incorporate public-key cryptographic signatures for strict anti-tampering verification.
These are engineering scale-up milestones, not structural deficiencies in the core offline architecture.
